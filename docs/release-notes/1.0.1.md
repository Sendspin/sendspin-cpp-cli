A fix for local pairing on Home Assistant OS, and a config file in the Linux packages. The
player still speaks Sendspin 1.0.0-rc1, and nothing breaks for CLI users: every flag, config
key, control-socket message, state-file format and exit code from 1.0.0 works the same way.

### Fixed issues

- **Local pairing works on Home Assistant OS.** `--pairing-token-endpoint` now answers a peer
  whose address is one of this host's own, as well as peers on the endpoint address's subnet.
  Music Assistant runs on the host network, so its fetch of `172.30.32.1` was masqueraded to
  the host's LAN address and refused with 403. Music Assistant then logged
  `Fetching the local token of <id> failed: HTTP 403` and never paired by itself. Other
  machines on the LAN are still refused. (#134)

### Packaging

- **The `.deb`, `.rpm` and Arch packages install `/etc/sendspin-cli.conf`.** It is the fully
  commented example, so nothing changes until you edit it. Upgrades keep your edits: it is a
  deb conffile, an rpm `%config(noreplace)` and an Arch `backup`. The package still doesn't
  enable or start the service. Installation → Packages walks through configuring it. (#130)
